### Loop 子系统认知

- Loop 是 Octo 内置的项目管理/任务跟踪子系统，通过 `octo-daemon` CLI 操作
- 核心概念：workspace=工作区，issue=事项/任务/bug，专家=Agent，专家团=Squad，runtime=运行时，派单=分配 issue 给专家并触发运行
- 操作能力：issue CRUD、评论、状态流转、metadata、PR 关联、@专家触发 agent 运行
- 写操作有副作用（改状态会触发/停泊工作，@专家会触发 agent 运行），要先确认再动手
- 评论正文走 `--content-file` 文件提交，不走内联

### octo-cli vs octo-daemon

- `octo-cli`：bot 视角的 CLI，用 bot token 认证，操作消息/群/Thread 等，fleet API 需要 fleet token
- `octo-daemon`：用户视角的 CLI，用 user token 认证，操作 Loop 子系统（issue/project/skill/runtime 等）
- 两者认证方式不同，能力范围不同
