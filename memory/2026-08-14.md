## Octo Loop 功能培训会议总结

小胡分享了 Octo Loop 功能专场培训的会议总结（会议时间 2026-07-20，主讲人：王一林）。

### 核心概念

**Loop Engineering**：硅谷热门概念，从 Prompt Engineering 转向 Loop Engineering。
- 分钟级 Agent Coding Loop（Agent 间协作）
- 小时级 Developer Feedback Loop（人给 Agent 反馈）
- External Feedback Loop（基于现实数据和协作的反馈）

### Opto Loop 产品定义

**两类 AI 角色：**
1. **助理（Assistant）**：有长期记忆、懂用户偏好、管理其他 Agent、归属个人、入口在 IM
2. **专家（Expert）**：无长期记忆、作为计算资源/执行者、上下文干净、归属可设置（私有/公共）、入口在 Loop

**Loop 工作流：**
用户在 IM 给助理下达任务 → 助理在 Loop 创建任务 → 专家/专家团（Squad）接单执行（A to A 循环）→ 结果带回 IM

**专家能力三层配置：**
1. 指令（系统提示词，定义角色边界）
2. 技能（Skill 组合）
3. Webhook（任务状态变化时通知 IM，实现自动化闭环）

### 五大核心痛点
1. 智能体原生记忆功能不足（如 OpenClaw 的 memory.md 维护困难）
2. 多 Agent 并发时用户角色疲惫，注意力分散
3. IM 聊天窗难以追踪长程任务进度
4. 团队缺乏可共用的"公家虾/部门虾"专家 Agent
5. IM 适合沟通但不适合任务追踪

### 研发最佳实践
1. 任务（Issue）初始描述应由 Bot 生成结构化 PRD，而非人工编写
2. 专家需专人专事，技能控制在 10 个以内，注重通用性
3. 工作流通过提示词描述阶段和目标，具备反思和自动修复能力

### 核心价值
将人的注意力从执行阶段解放，聚焦于关键决策点（方案评审、冒烟测试验收）。
