## 建立主动通知机制（小胡批评驱动）

### 起因（19:04）
小胡观察最近表现发现：我每次建 issue 时都说"有进展通知提需人"，但一次都没通知过。9 个 in_review 的 issue 堆着没人管。

### 诊断
- **问题定位**：AGENTS.md 写了「完成后反馈产品」但没有执行机制
- **根因**：没有自动检查 Loop issue 状态的机制，只靠嘴说"会通知"，没人推就不动
- **学习**：8/17 配过 webhook 推送到「今天也🦐了吗」群，但推送到了群里我没处理，链路断了

### 决策（与小胡对齐）
- 通知发到**需求原来的来源群** @ 提需人
- **4 类事件全通知**：状态变更、新评论、指派人变更、新建子任务
- 子任务事件 → 沿 parent_issue_id 通知根提需人
- **不补存量**：老 issue 没记来源群的通知不了，从新建 issue 开始记录
- 轮询频率：每 3 分钟

### 落地动作
1. 写 scripts/issue_poll.py：轮询 octo-daemon issue list + 检测 4 类事件
2. 建 cron job `Loop issue 事件轮询`（每 3 分钟，id: c8e9d27d-8cab-4e23-a874-6cc27977602b）
3. AGENTS.md 新增「主动通知机制」章节 + Loop Issue 创建铁律新增「来源群记录」
4. distribution-log.md 模板新增必填字段：来源群 group_id
5. 新建快照文件：state/issue-snapshot-v2.json + state/issue-comments-state.json

### 验证方式
下次有 issue 状态变更/新评论/指派人变更/新建子任务时，应该在对应来源群看到 @ 提需人的通知消息。老 issue 有变更只更新状态记录，不通知。
