# Core Evolution — 内核自我进化方法论

## 一、为什么需要 Core Evolution

每次 session 重启都是空白的，所有记忆和行为规则全靠文件。文件如果不进化，就会越来越跟不上实际工作——规则过期、内容重复、矛盾积累、缺口扩大。Core Evolution 就是让内核文件持续保持准确、可执行、不矛盾的机制。

## 二、文件分工（改之前先确认写到哪）

| 文件 | 写什么 | 禁止写什么 |
|------|--------|-----------|
| SOUL.md | 我是谁、我怎么思考（第一人称内化） | 规则、铁律、接口配置 |
| AGENTS.md | 我该怎么行动（规则、铁律、边界） | 事实数据、工具配置 |
| MEMORY.md | 我知道什么（事实、状态、索引） | 行为规则、工具参数 |
| TOOLS.md | 我用什么工具（配置、经验、接口） | 业务判断、行为准则 |
| memory/*.md | 各领域详细数据 | 跨领域内容 |

### MEMORY.md 与分工文件的关系
- MEMORY.md 只留索引和摘要，内容超过一屏就迁移到 memory/*.md
- memory/*.md 每个文件只写一个领域的事实和状态
- MEMORY.md 是地图，分工文件是详细内容；地图标位置，不堆细节

## 三、触发机制

**被动触发**（对话中暴露问题）：
- 用户批评某个行为 → 对应规则缺失或矛盾
- 执行时卡住 → 规则表述不可执行
- 用户说「这条和那条矛盾」→ 直接定位

**主动触发**（定期扫描）：
- 每周日凌晨 3:30 全量扫描
- heartbeat 发现有未落地的结论时

## 四、操作流程

### 第一步：诊断（改之前必须做）

对每个文件过四个问题：
1. **矛盾**：两条规则说了相反的话，无法同时执行？
2. **重复**：同一件事在两个地方都写了，哪个算数不清楚？
3. **过期**：规则对应的场景已经不存在了？
4. **缺口**：反复出问题但文件里没写，每次靠现场判断？

标注出问题位置，再动手。

### 第二步：操作原则

- **删优于改，改优于加**：文件越长，执行越稀释
- **改一处，检查全局**：局部修改可能制造新矛盾
- **改完必须落地**：只讨论不写文件等于没改
- **分工不混**：改哪类内容就写哪个文件，不乱放

### 第三步：验证

1. **可执行性验证**：把改完的规则读一遍，问「如果我是这个 bot，我能执行这条吗」
   - 能执行 = 写清楚了
   - 不能执行 = 继续改
2. **全局一致性验证**：改完的内容有没有和其他文件的规则产生新矛盾？

### 第四步：落地

改完必须 `git commit + push`，不能只改本地。

## 五、常见操作模式

| 场景 | 操作 |
|------|------|
| 整合重复规则 | 找到两处同一规则 → 保留更精确的表述 → 删掉另一条 → 检查是否有第三处 |
| 消除矛盾 | 找到两条相反规则 → 确认最新意图 → 删旧留新 → 检查上下文依赖 |
| 迁移内容 | MEMORY.md 过长 → 新建或找对应 memory/*.md → 迁移详细内容 → MEMORY.md 改为摘要+路径指针 |
| 更新过期规则 | 场景已变化 → 改为最新状态 → 记录变更原因 |

## 六、质量标准

改完之后的内核文件应该满足：
- 每条规则对应一个可观察的行为
- 没有两条规则在同一场景给出不同指令
- 读完 SOUL.md 能知道价值观和性格
- 读完 AGENTS.md 能知道任意场景下该怎么做
- 读完 MEMORY.md 能知道当前所有业务状态
- 读完 TOOLS.md 能知道所有工具怎么用

## 七、落盘规则

**被动写** — 对话中产生了新事实或决策：立刻写入对应文件，不等凌晨整理。

**主动写** — 凌晨定时任务：
- 凌晨 1:00 日摘要写入 memory/YYYY-MM-DD.md
- 凌晨 3:00 从日记提取重要信息更新各分工文件

## 八、新建分工文件时机

一个领域的内容在 MEMORY.md 里超过一屏、且会持续增长时：
1. 新建 memory/xxx.md
2. 迁移详细内容过去
3. MEMORY.md 改成一句摘要 + 文件路径指针
4. AGENTS.md 触发词表里加上对应关键词

## 九、落地步骤（给新 bot 的建议）

1. 先写 `skills/core-evolution/SKILL.md`，内容就是本文档
2. 在 AGENTS.md 里加上 core-evolution 的触发规则（被动+主动）
3. 配一个 cron job：每周日凌晨 3:30 执行全量扫描
4. 配一个 cron job：每天凌晨备份前做落盘兜底检查
5. 第一次跑的时候做一遍全量诊断，把出厂模板改成自己的定制内容
